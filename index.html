Why this exists

Minew's ACC frame layout, units and axis signs are not published. Instead of guessing offsets, this lab learns them from your beacon: you place it with six sides up, capture a packet for each, and it finds the three bytes-fields whose vector always has the same length (gravity) and points in six different directions, then solves the axis mapping. Everything is stored locally and can be edited by hand below.

What BeaconSET+ does, and what this web app can't

BeaconSET+ connects to the beacon over a Bluetooth connection, asks for the beacon's 8-character password (the factory default is minew123), reads the six frame slots and writes your changes back. Minew's SDK guide describes this (password prompt, six slots, advertising interval, TX power, ACC parameters, triggers, connectable on/off) but does not publish the Bluetooth service/characteristic IDs or the bytes used for the password and the writes. A browser page can't repeat that handshake without them, and guessing could lock the beacon. That is why the GATT Console drops out: the beacon hangs up when no valid password arrives.

Use BeaconSET+ to change settings; use this app only to read the broadcast. Below is what to check in BeaconSET+ so the broadcast carries the data this app needs.

Optional: unlock real configuration in this web app

Android can record the Bluetooth traffic between BeaconSET+ and your beacon. From that recording the exact service IDs, the password message and the write messages for your beacon can be read out and built into this page. Steps on your realme phone:

  1. Settings → About phone → tap Build number 7 times. Then Settings → Additional settings → Developer options → turn on Enable Bluetooth HCI snoop log (if there are options, choose "Enabled" / "Full"). Turn Bluetooth off and on.
  2. Open BeaconSET+, connect to the beacon with the password, open the ACC slot, change the advertising interval a little (e.g. 1000 → 900 ms), Save, change it back, Save, then disconnect.
  3. Developer options → Take bug report → Full report. When it finishes, share the zip file to yourself and attach it in the chat with Claude.
The recording contains the beacon's MAC address and the password you typed. If it's still the default minew123 that's harmless; if you set your own password, change it afterwards. Only share it with someone you trust. Even with the recording, write support can't be promised; a wrong write can lock the beacon.

Privacy

    
    
      
  • One static file. A Content-Security-Policy blocks every network request (connect-src 'none'), so it cannot upload anything.
    • 
      
  • Settings and decoder config are in this browser's localStorage. Packet history is kept in memory only and is gone when you close the tab; export is a manual download.
    • 
      
  • Bluetooth permission is granted by your browser per device; this page never sees MAC addresses.
    • 
      
  • The beacon's advertisements are not encrypted. Anyone with a BLE scanner nearby can read them; this page does not change that.
    • 
    

    

  

  

    
Limits

    
    
      
  • Requires Chrome / Edge on Android or desktop over HTTPS or localhost. Safari and Firefox have no Web Bluetooth.
    • 
      
  • Passive scanning needs chrome://flags/#enable-experimental-web-platform-features. Without it, use "Add beacon (picker)", which only watches the one beacon you pick.
    • 
      
  • Accelerometer only: tilt is valid while the beacon is still. Yaw (rotation about vertical) can't be known, and fast motion shows "uncertain". Packets arrive about once per second at your configured interval.
    • 
      
  • The ACC byte layout is learned from your device in the Decoder Lab. Nothing here is a verified Minew decoder until you've run that on your beacon.
    • 
      
  • Standard frames decoded here: iBeacon, Eddystone UID / URL / TLM.
